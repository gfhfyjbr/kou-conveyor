# UX-аудит `cmd/` (kou-conveyor-runner · kou-conveyor-tui · kou-conveyor-web)

Дата: 2026-09-28. Метод: чтение исходников `cmd/` (~70 K строк без vendor), README/доки,
скриншотов из репозитория, плюс контрольный рендер TUI через временный тест
(терминалы 80×24 и 60×18, состояния idle/running/`/`/`/clear`) и запуск runner без ключа.
Строки кода указаны по текущему состоянию рабочей копии.

Легенда серьёзности:
**[!!!]** — теряет данные/деньги или сбивает с толку в базовом сценарии ·
**[!!]** — заметно путает или утомляет · **[!]** — портит впечатление, шероховатость.
Категория: 🌀 путает · 😵 перегружает · 💔 портит впечатление.

## 0. Резюме

Продукт очень функциональный и вылизанный визуально, но UX-проблемы в основном **системные**,
а не точечные:

1. **Одни и те же слова означают разное** (`compact`, `continue`, `resume`, `fork/branch/duplicate`,
   `effort/thinking/think`, `inspector/sidebar`), а одни и те же клавиши делают разное
   в зависимости от контекста (Ctrl-C ×4, Ctrl-D ×3, Ctrl-T ×3, Tab ×3, ↑ ×3, Enter ×5).
2. **Перегруз подсказками и хоткеями**: в TUI до 13 подсказок в футере и одна и та же подсказка
   в 4 местах одновременно; в web ~30 однобуквенных глобальных хоткеев без модификаторов,
   37 строк в шпаргалке, палитра с сотнями пунктов.
3. **Опасные действия без страховки или с тремя разными паттернами подтверждения**:
   удаление сессии (пикер / «click again» / `window.confirm` / Ctrl-D дважды), очистка очереди
   и `Backspace` в очереди — без подтверждения, `Ctrl-C` в idle стирает черновик с картинками,
   `n` в web создаёт новую сессию, `/c`+Enter в web запускает `/compact` (платный вызов модели).
4. **Утечка внутренних терминов** в интерфейс: `runner default`, `CLIProxyAPI 7.3.16`,
   состояние `config.yaml`, режим `-provider · the server's flag`, `RESPONSES/MESSAGES`,
   `KOU_CONVEYOR_LLM_*`, «Runner log», сырой stderr раннера в строке статуса.
5. **Непоследовательность между двумя кокпитами**: разные клавиши для одного действия,
   разные формы настройки соединения, разные наборы функций (история промптов только в TUI,
   Reuse/Branch по кнопке — только в web).
6. **Подтверждённые визуальные дефекты** в TUI: обрезанная подсказка команд (видно 6 из 26),
   пропавший пробел `/resume<id>`, welcome-экран не влезает в 80×24, «SESSION · NEW» после `/clear`
   существующей сессии.

## 1. Сквозные проблемы (обе оболочки)

### A1 [!!!] 🌀 «compact» означает две несвязанные вещи
- `/compact` — сжать контекст (модель пишет summary). `-compact` флаг TUI и константа
  `LayoutCompact` — inline-раскладка. `cmd/kou-conveyor-tui/main.go:59` до сих пор публикует флаг
  с подписью *«the former name of -inline»*; `compact.go:17` признаёт: «Compact, called inline on
  screen since /compact compacts the conversation». В `-h` пользователь видит `-compact`, в UI
  видит `/compact` и слово «Compacting context» — и ожидает связь.
- Рекомендация: удалить `-compact` (или спрятать из `-h`), переименовать внутренний режим в `inline`.

### A2 [!!!] 🌀 `-continue` ≠ `/continue`, `-resume` ≠ `/resume`, «Continue» ≠ «Resume»
- `-continue` (флаг) = открыть самую свежую сессию; `/continue` (команда) = дослать модели
  «Continue where you left off.»; `-resume` = открыть пикер; `/resume <id>` = открыть по ID;
  кнопка **Continue** в web-баннере = `/continue`; **▶ Resume** в очереди = снять паузу очереди.
  `main.go:47-48`, `model.go:1264-1276`, `session.js:29` (`CONTINUE`), `queue.js:26`.
- Пять сущностей на два слова. Предложение: флаги `-last`/`-pick`, команда `/continue` →
  «Pick up» / «Finish the run», кнопка очереди «Run queue».

### A3 [!!] 🌀 Fork / Branch / Duplicate — три названия и одна команда с двумя смыслами
- `/fork` без аргумента дублирует сессию, `/fork n` ветвит перед промптом n (`manage.go:117`,
  `session.js:1049` с алиасом `branch`). В меню — «Duplicate», в таймлайне — «Branch», в палитре
  TUI — «Branch before a prompt…» и «Duplicate the session». В README — «Branch».
- Разнести на `/duplicate` и `/branch n`, одно слово в UI.

### A4 [!!] 🌀 Effort / thinking-level / think / reasoning
- Флаг `-thinking-level`, UI «EFFORT», алиас `/think`, шпаргалка «next effort level», inspector
  «Effort», usage «Reasoning tokens». Уровни `low medium high xhigh max`: порядок `xhigh` < `max`
  неочевиден («extra high» интуитивно максимум).

### A5 [!!] 🌀 Inspector vs Sidebar vs «Hello»
- Инспектор стал вкладкой сайдбара, но остался хоткей `I` (inspector.js:228) рядом с `S`
  (sidebar.js:512): обе клавиши открывают одну панель; в палитре есть и «Show sidebar», и
  «Show inspector». Пустое состояние сайдбара — вкладка с именем **«Hello»** (sidebar.js:444),
  кнопка «+» открывает «Hello». Пользователь ждёт «New tab» / «Empty».

### A6 [!!] 💔 Внутренние термины в интерфейсе
- «runner default» / «runner defaults» как значение модели и подпись режима ENVIRONMENT
  (`models.go`, `settings.go:16-22`, `connection.js:78`).
- Хлебная крошка `CLIProxyAPI 7.3.16` на вкладке Accounts (accounts.js:81), состояние аккаунта
  «config.yaml» и фильтр «Keys in config.yaml» (gateway.js:14).
- Режим соединения с подписью «**-provider** · the server's flag» (gateway.js:431) — имя CLI-флага
  как элемент управления.
- Типы API «RESPONSES / MESSAGES» вместо «OpenAI / Anthropic» (протокол вместо провайдера);
  «ENVIRONMENT» как «тип провайдера».
- Тексты с `KOU_CONVEYOR_LLM_PROVIDER, _BASE_URL, _API_KEY и _MODEL` прямо в форме.
- «Runner log» в инспекторе; в TUI сырой stderr раннера показывается в строке статуса
  (`view.go:1145`, `1172`; `model.go:711-716`) — например `plugin> …` или «unreadable runner output».
- Пользователь-непрограммист (а web-кокпит явно на него рассчитан — есть мобильная вёрстка)
  не должен знать слова runner, gateway, CLIProxyAPI, config.yaml.

### A7 [!!] 🌀 Разные клавиши/функции для одного действия в двух кокпитах
| Действие | TUI | Web |
|---|---|---|
| Панель изменений | `^G` (мнемоника? «git»?) | `D` |
| Список сессий | `^S` | `/` (фильтр), `J`/`K` |
| История промптов | `^R`, `↑` | **нет вовсе** |
| Модель | `^P` | `M` |
| `[` `]` | предыдущий/следующий промпт в панели изменений | вкладки сайдбара |
| `f` | follow в панели изменений | Files |
| Reuse/Branch по кнопке у промпта | нет (только `/fork n` по номеру) | есть |
| Подтверждение удаления | пикер Keep/Delete | «Click again» / `window.confirm` |
Пользователь, работающий в обоих (а это заявленный сценарий — общие сессии, общий effort),
постоянно промахивается.

### A8 [!!!] 🌀💔 Три паттерна подтверждения для одного разрушительного действия — и его отсутствие для других
- Удаление сессии: TUI пикер (`manage.go:71-93`); список сессий TUI — `Ctrl-D` дважды за 4 с
  (`manage.go:344`); web-меню `⋯` — «Click again to delete» (`session.js:878`); web-палитра и
  `/delete` — нативный `window.confirm` (`session.js:911, 1093`).
- Без подтверждения: **Clear** очереди (queue.js:28), `Backspace` на элементе очереди
  (queue.js:326 — в web даже без тоста), `/queue clear` в TUI (queue.go:628), `Ctrl-B` дублирует
  сессию (manage.go:335), `n` в web создаёт новую сессию.

### A9 [!!] 🌀 Конфигурация размазана по ~12 хранилищам, часть — только в браузере
- settings.json, preferences.json (effort/layout/ширина панели), workspaces.json, gateway.json,
  cliproxy/config.yaml, prices.json, usage.json, history.json, `.harness/ui-history.json`,
  `.harness/plugins`, `.env`, `~12` переменных `KOU_CONVEYOR_*`, плюс localStorage (тема, ширины,
  черновики, **модель сессии**).
- Модель, выбранная для сессии, живёт в localStorage вкладки (`models.js:138`) и в памяти TUI
  (`model.go:308`, `m.chosen`) → не переживает перезапуск TUI и не видна в другом браузере, хотя
  README обещает «The model chosen stays with the session». Effort при этом — на сервере.
  Пользователь не может предсказать, что «общее», а что «моё локальное».

### A10 [!!] 😵 Одна и та же подсказка в 3–4 местах одновременно
- В состоянии run в TUI (подтверждено рендером 80×24): placeholder «enter queues it… ctrl+x
  forces it in», метка рамки «PROMPT enter queues · ^X forces in», кнопка «⚡ FORCE ^X  QUEUE ↵»,
  футер «enter queue ^X force in», плюс строка статуса «esc esc stop» и футер «esc esc stop»
  и «^C stop». Шум, из-за которого настоящие уведомления (`notify`) теряются.

### A11 [!!] 😵 Объём хоткеев и справки
- TUI: шпаргалка `/help` — 36 строк без группировки (`model.go:1088`), в одной строке смешаны
  нотации «ctrl+s  ^E ^T ^B ^D»; футер использует `^K`, help — `ctrl+k`, web — `⌘K`.
- Web: 37 записей `help.keys`, 20 слэш-команд, 21 источник пунктов палитры.

## 2. TUI (`cmd/kou-conveyor-tui`)

### T1 [!!!] 🌀 Ctrl-C — четыре значения, одно из них стирает черновик
`model.go:1427-1449`: остановить ран → (в idle с текстом) **очистить композер вместе с
картинками, без undo** → предупредить → выйти (второе нажатие за 2 с). При выходе с очередью:
«queued messages are dropped». Ctrl-C — рефлекс «отмена/выход»; потеря набранного текста
и картинок — худший исход для рефлекторного нажатия.

### T2 [!!!] 🌀 Ctrl-D: выход / удалить сессию / удалить ключ
`model.go:1450` (выход), `manage.go:344` (в списке сессий — дважды удаляет выбранную),
`settings.go:211` (в форме — снять сохранённый ключ). Тот, кто привык, что `^D` = выход,
в списке сессий взводит удаление; второе нажатие «чтобы точно выйти» — удаляет сессию.

### T3 [!!] 🌀 Ctrl-T и Shift-Tab — по три роли
`Ctrl-T`: эффорт (`model.go:1492`) / pin в списке сессий (`manage.go:327`) / проверка
соединения в форме (`settings.go:209`). `Shift-Tab`: эффорт в композере, «назад» в форме
и пикере. Shift-Tab как «следующий уровень эффорта» противоречит общепринятому «фокус назад».

### T4 [!!] 🌀 Esc Esc в idle = редактирование последнего промпта
`edit.go:42-75`. Одиночный Esc ничего не делает (только «взводит»); двойной — подменяет
содержимое композера текстом последнего промпта (черновик уходит в `edit.draft`, но визуально
«текст пропал»). Двойной Esc — рефлекс «закрыть всё».

### T5 [!!] 🌀 Модальные клавиши, зависящие от содержимого композера
- `↑` (`model.go:1576`): фокус на очередь / история / перемещение по строкам.
- `Home`/`End` (`model.go:1543`): скролл транскрипта только при пустом композере.
- `Tab` (`model.go:1569`): автодополнение команды / фокус на панель изменений / ничего; после
  фокуса на панели «любая клавиша возвращает в композер» — невидимая модальность.
- `Enter` в списке `$`-ссылок без выбора стрелками **отправляет промпт** (`links.go:179-183`).

### T6 [!!!] 💔 Подсказка команд в строке статуса обрезается; пропал пробел
`view.go:1080-1097`: все совпадения склеиваются в одну строку и режутся `fit()`. При «/» на
80 колонках видно **6 из 26** команд, без скролла и списка (в web — нормальный popup).
Баг: `strings.TrimSpace(" "+c.args)` (`view.go:1089`) съедает разделитель →
`/resume<id>`, `/queue[resume|pause|clear]` (подтверждено рендером).

### T7 [!!] 🌀 Tab-дополнение берёт первое совпадение без перебора
`model.go:1666-1682`: «/c» → `/continue` (хотя есть compact/copy/collapse/clear/changes),
«/e» → `/edit`. Повторный Tab ничего не меняет.

### T8 [!!!] 🌀 `/clear` и Ctrl-L превращают существующую сессию в «новую» на вид
`model.go:1335-1340`, `1500-1506`; `view.go:667`. После `/clear` показывается welcome-карточка
**«SESSION · NEW»**, стартовые задачи и заголовок «New session <id>» (подтверждено рендером),
хотя сессия старая и следующий промпт допишется к её истории (`Resume: !m.fresh`). Вернуть
транскрипт можно только переоткрыв сессию. `Ctrl-L` в терминалах — «перерисовать экран»,
здесь — «спрятать историю».

### T9 [!!] 😵 На 80×24 chrome занимает 11 строк из 24; welcome не влезает
`view.go:81-89` + композер min 3 строки + рамка. Транскрипту остаётся 13 строк: карточки
задач обрезаны на половине, строка «click use a task…» не видна (подтверждено рендером).
Wordmark «READY» из блок-символов занимает 4 строки. Строка «air» под шапкой и пустая
строка внутри композера — роскошь на стандартном терминале.

### T10 [!!] 😵 Placeholder на 107 символов
`model.go:671`. На 80 колонках переносится на две строки, на 60 обрезается на «shift+enter,»
(подтверждено). Три способа перевода строки перечислены в placeholder, при этом футер
показывает только `^J`.

### T11 [!!] 😵 Футер: до 13 подсказок, спорный приоритет
`view.go:1345-1385`: idle — enter run · ^J · ^V image · esc esc edit · ^T effort · ^K · ^G ·
^F · ^S · ^R · ^O · drag copy · ^C quit. `keyHints` отбрасывает с конца → на узком экране
первым исчезает «^C quit», а «^V image» стоит раньше «^K commands» и «^S sessions».
В running: и «esc esc stop», и «^C stop».

### T12 [!!] 💔 Строка статуса — единственный канал уведомлений, и она «мигает»
`model.go:1373-1381`: одно сообщение, новое затирает предыдущее (ошибка на 6 с перекрывается
`effort: high` через секунду); журнала нет. Та же строка занята hover-подсказкой, которая
меняется при каждом движении мыши (`view.go:780`, `tea.WithMouseAllMotion`) — текст
«click folds it away / click shows it in full» скачет при любом жесте.

### T13 [!!] 🌀 `-session <id>` с опечаткой молча создаёт новую сессию
`main.go:165-171`: «anything else is a new one». Пользователь ждал старую сессию, получил
пустую с чужим ID.

### T14 [!!] 🌀 Ctrl-V перехвачен под картинку
`model.go:1518`, `attach.go:77-92`. На Linux/Windows терминалах Ctrl-V/Ctrl-Shift-V — вставка
текста; здесь сначала читается изображение из буфера, текст — запасной путь. Терминальная
вставка (bracketed paste) при этом работает как обычно — два пути с разным поведением.

### T15 [!!] 💔 Панель изменений запоминает «открыто» и в узком терминале накрывает всё
`changes.go:752` (порог 110 колонок), `model.go:317` (`prefs.Changes`). Открыл на широком
мониторе → следующий запуск в 100-колоночном терминале начинается с панели «No changes were
recorded for this prompt.» поверх транскрипта.

### T16 [!] 🌀 Inline-режим — «урезанная» версия, о чём узнаёшь по факту
Нет мыши, нет `✎ edit`, нет панели изменений (Ctrl-G уводит в fullscreen), `Ctrl-O` действует
только «отсюда и дальше», PgUp/PgDn не работают (`model.go:1470-1533`, `compact.go`).
Уведомления вида «tool output and thinking show in full from here on · ^F shows all of it».

### T17 [!] 🌀 Первый запуск без ключа: совет продолжить вместо совета настроить
Run стартует, тут же `ERROR KOU_CONVEYOR_LLM_API_KEY or OPENAI_API_KEY must be set`, и строка
статуса говорит «the run failed before it finished — **/continue** picks it up, esc esc edits
the prompt» (`model.go:803-807`). Правильный совет — `/settings`. При этом `Init()` предлагает
`/settings` только если файл настроек повреждён (`model.go:339-343`).

### T18 [!] 💔 «◌ interrupted — /continue picks it up» висит после намеренной остановки
`view.go:1177, 1189`. Остановил ран сам → постоянный жёлтый баннер в статусе.

### T19 [!] 🌀 `Ctrl-P` открывает пикер моделей, но не закрывает
`model.go:1600-1608`: `^K/^S/^R` работают как toggle, `^P` внутри пикера = «вверх»
(`picker.go:167`).

### T20 [!] 💔 Форма `/settings`: смесь транспорта, источника и протокола
`settings.go:16-22`: «GATEWAY / ENVIRONMENT / RESPONSES / MESSAGES» в одном сегментном
контроле; поле модели без списка (после `^T` — до 6 подсказок одной строкой).

### T21 [!] 💔 `/rename` без аргумента кладёт `"/rename <старый заголовок>"` в композер
`manage.go:38-45` — редактирование через командную строку; в web — inline-поле.

## 3. Web (`cmd/kou-conveyor-web`)

### W1 [!!!] 🌀💔 ~30 однобуквенных глобальных хоткеев без модификаторов
`host.js:496` разрешает их всегда, когда фокус не в поле ввода. После клика по транскрипту
(выделить текст) фокус уходит из композера, и попытка набрать «new session» даёт:
`n` — новая сессия (`session.js:1069`, без подтверждения), `e` — раскрыть все инструменты,
`w` — меню workspace, `s` — сайдбар… Также `t` переключает тему всей страницы (`theme.js:25`),
`a`/`u` уводят в Accounts/Usage, `j`/`k` (`session-list.js:313-314`) переключают сессии и
зарегистрированы **без `views`** → срабатывают и внутри Accounts, выдёргивая из раздела.

### W2 [!!] 🌀 Частичная поддержка русской раскладки
Кириллические дубли есть только у `` ` ``→`ё` (terminal.js:265), `f`→`а` (explorer.js:516) и
`Mod+в/л/ц/е` в терминале. `n/m/s/d/e/g/i/t/a/u/w/c` — нет. Пользователь в русской раскладке
получает случайный набор работающих клавиш.

### W3 [!!!] 🌀 Enter в списке команд запускает лучшее нечёткое совпадение
`commands.js:246` + `201`: «/c» + Enter → первое совпадение `/compact` (args `[focus]` не
начинается с `<`) → **сразу** `composer.submit()` → платный вызов модели и замена контекста
