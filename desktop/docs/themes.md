# Темы и настройки kou desktop

## Карта проекта и точки интеграции

Репозиторий содержит несколько отдельных приложений: Go runner и кокпиты в
`cmd/`, общий Go harness в `harness/`, Rust-сервер и движок в `apps/` и
`crates/`, iOS-клиент в `ios/`. Нативное приложение в `desktop/` — отдельный
Cargo workspace. Изменения оформления относятся к этому workspace.

| Компонент desktop | Ответственность |
| --- | --- |
| `kou-desktop` | Окно GPUI, пространства, сессии, вкладки, жизненный цикл панелей, настройки и сохранение состояния |
| `kou-ui` | Общие цветовые токены, метрики, иконки, небольшие элементы управления |
| `kou-thread` | Независимая от интерфейса модель разговора, команды и обновления бэкенда |
| `kou-thread-view` | Транскрипт, редактор сообщения, очередь, режимы Cockpit и Studio |
| `kou-native` | Подключение собственного агента через Go runner |
| `kou-acp` | Подключение агентов через Agent Client Protocol |
| `kou-claude` | Прямое подключение Claude Code и поддержка фонового процесса |
| `kou-agents` | Поиск установленных harness, запуск и определение состояния |
| `kou-term` / `ghostty-vt-sys` | PTY, эмуляция терминала и отрисовка |
| `kou-canvas` | Узлы с живыми панелями, связи, перемещение и масштабирование |
| `kou-plugins` | JavaScript-плагины интерфейса, декларативные деревья элементов и горячая перезагрузка |
| `kou-ipc` / `kou-mcp` | Локальный IPC, CLI и инструменты для взаимодействия агентов с приложением |
| `kou-usage` | Состояние аккаунтов и лимиты провайдеров |

Оформление настроек целиком описывается JS-плагинами `screens` и `appearance`.
Оболочка окна — `workspace`, поле ввода — `composer`. Rust хранит состояние,
проверяет документы и выполняет команды. Для обязательных экранов при ошибке
пользовательского скрипта используется встроенная JS-версия. Остальные части
сохраняют нативный резерв. См. [границы JS и Rust](js-ui.md).

Цвета уже были централизованы в `kou-ui::Palette` и GPUI global `Theme`.
`plugin_view::theme_json` передаёт ту же палитру плагинам. Терминалы получают
её через `terminal_style`; при переключении темы `retheme` обновляет запущенные
терминалы, а `refresh_windows` перерисовывает интерфейс. Кеши рисунков плагинов
учитывают палитру. Новая реализация использует эти существующие механизмы.

## Что добавлено

- Три встроенные темы: **Charcoal**, **AMOLED Black**, **White**.
- Charcoal следует тёплому тёмному референсу: боковая панель `#141412`,
  рабочая область `#1A1A18`, близкие по яркости поверхности, оранжевый акцент
  `#FF7C30` и светлая основная кнопка `#EEEDE7`.
- Разделы **Appearance**, **General**, **Agents & accounts**, **Keyboard shortcuts**.
- JS-редактор оформления с нативным вводом текста, проверкой и сохранением.
- Создание темы на основе текущего оформления, изменение названия, редактирование
  сохранённой темы, удаление и применение.
- Все 26 токенов палитры: поверхности, текст, действия и статусы. Выбор из
  образцов или ввод точного `#RRGGBB`; локальный предпросмотр и предупреждение
  о недостаточном контрасте основного текста и кнопки отправки.
- **Reset colours** возвращает цвета исходного пресета. **Cancel** отбрасывает
  черновик. Только **Save & apply** сохраняет и применяет изменения.
- **Copy theme link** экспортирует активное оформление. **Import from link**
  открывает предпросмотр; сохранение добавляет отдельную пользовательскую тему.

Редактор не перекрашивает само окно до сохранения. Поэтому даже полностью
нечитаемый экспериментальный цвет можно исправить, не потеряв доступ к
элементам управления. Шрифты, размеры, изображения фона и отдельные ANSI-цвета
не входят в формат темы; ANSI-набор выбирается по светлой/тёмной основе.

## Данные и совместимость

`kou-ui/src/themes.rs` содержит `Preset`, `ThemeDocument`, `Selection` и
`SavedTheme`. В существующий `state.json` добавлены поля `theme` и `themes`.
Идентификатор сохранённой темы не меняется при редактировании или переименовании.
Сохранение выполняется существующим атомарным механизмом `Store::save`.

Новая установка начинает с Charcoal. Файл старой версии без поля `theme`
сохраняет прежнее поведение: следование системной теме и существующий `accent`.
Явный выбор пресета или пользовательской темы больше не переопределяется
сменой оформления macOS. **Follow system** возвращает автоматический выбор.
Неизвестная или невалидная активная пользовательская тема даёт безопасный
запасной Charcoal. Сессии, аккаунты и панели не мигрируют и не удаляются.

## Ссылки

Формат: `kou-theme://v1/<base64url(JSON)>`, без padding. JSON содержит только:

```json
{
  "version": 1,
  "name": "My theme",
  "base": "charcoal",
  "colors": { "rail": 1315858, "pane": 1710616 }
}
```

Это сокращённый пример структуры: настоящая ссылка содержит **все 26** полей
`Palette`. Имена баз: `charcoal`, `amoled-black`, `white`.

Ссылка самодостаточна: сервер, загрузка ресурсов и учётная запись не нужны.
В ней нет путей проектов, истории переписки, настроек аккаунтов или ключей.
Импорт проверяет версию, структуру, имена полей, диапазон RGB, длину имени
(1–64 символа без управляющих символов) и общий размер ссылки (до 8192 байт).
Неизвестные поля и неполные палитры отклоняются. Библиотека ограничена 64 темами.

- macOS: `Info.plist` регистрирует `kou-theme`, а `Application::on_open_urls`
  передаёт ссылку в предпросмотр. Требуется обновлённый app bundle.
- Linux: desktop entry объявляет `x-scheme-handler/kou-theme` и передаёт URL
  через `%u`; установочный скрипт сохраняет этот аргумент.
- На любой платформе доступен импорт вставкой ссылки в настройках и
  `kou-desktop --theme-link 'kou-theme://v1/…'`. Ссылка как позиционный аргумент
  также принимается. Отдельная регистрация протокола в реестре Windows не добавлена.

Не все мессенджеры превращают пользовательские URI-схемы в кликабельные ссылки;
в таком случае получатель копирует ссылку в **Import from link**.

## Инпут и принудительная доставка

Убраны рамка и анимация рамки внешнего инпута в JavaScript-плагине, Cockpit
fallback и Studio. Это относится к idle, busy, focus и drag-over; при
перетаскивании файлов меняется только фон. Внутренние кнопки и выбор модели
сохраняют собственные индикаторы фокуса. Геометрия подсказок инпута скорректирована
на удалённый пиксель рамки.

Пользовательское сообщение больше не получает акцентную вспышку при появлении.
Это действует и для forced-сообщений, которые бэкенды уже преобразуют в обычные
`UserChunk`. У ожидающего forced-сообщения убрана акцентная полоса, иконка стала
нейтральной. Порядок очереди, steering, остановка неподдерживающего steering
агента и повторная отправка не изменены.

## Проверка

```sh
cd desktop
cargo test -p kou-desktop -p kou-ui -p kou-thread-view
cargo build -p kou-desktop
```

На машине проверки Xcode требует принятия лицензии. Сборка и тесты выполнены
через установленные Command Line Tools и поддерживаемую GPUI опцию:

```sh
DEVELOPER_DIR=/Library/Developer/CommandLineTools \
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk \
script/capped --jobs 4 -- cargo test \
  -p kou-desktop -p kou-ui -p kou-thread-view \
  --features gpui_platform/runtime_shaders
```

Проверяются round-trip ссылок с Unicode, отклонение повреждённых данных,
контраст пресетов, сохранение и восстановление сессий вместе с темами,
совместимость старого состояния, редактирование без смены идентификатора,
отмена черновика и отсутствие рамки инпута во всех состояниях плагина.
Существующие проверки forced-доставки и очереди также входят в прогон.

Для визуальной проверки добавлены сцены `shell-settings-charcoal`,
`shell-settings-white`, `shell-settings-editor`. Проверены также существующие
сцены общих настроек и работающего агента. Клик по зарегистрированной ссылке
из внешнего приложения отдельно не проверялся; импорт, CLI-разбор и bundle
проверяются без изменения регистрации приложения пользователя.
