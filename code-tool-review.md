# Ревью Code-тула и новых тулов

Что проверено: Code (codevm, harness/tool/code, operation/code), Read/Edit/Write/apply_patch (fileops, operation/file, tool/file), TranscriptSearch, профили тулов, таймаут Bash, раздел Code tool в системном промпте, docs.

## Как теперь устроен результат Code

- На каждый вызов одна строка: `- name: аргументы (exit N, длительность)`. Разделители `|` убраны. Для applyPatch в строке перечислены файлы (`Update a.go, Add b.go`), а не `*** Begin Patch`.
- Вывод вызова показывается, только если вызов упал (ошибка или ненулевой exit) или если код ничего не залогировал и не вернул. Иначе вместо выводов стоит пометка `(The outputs of the calls that succeeded are left out: …)`. Раньше каждый вывод (до 4000 символов) повторял то, что код уже вернул: в этой сессии каждый readText был виден дважды.
- Значения показываются так, как их показал бы JS:
  - используется JSON.stringify из VM, поэтому ключи идут в порядке вставки;
  - Error выводится как стек, без фреймов Go (native);
  - Map и Set выводятся со своим содержимым;
  - Promise выводится с подсказкой «await it»;
  - `throw {code: 7}` даёт `uncaught {"code":7}`;
  - у отказов тулов больше нет префикса `GoError:`.
- Аргументы проверяются строго. Нестроковый аргумент или неизвестная опция дают TypeError со списком допустимых опций. Ошибки edit используют имена из JS: oldString и `{ replaceAll: true }`.
- Устойчивость:
  - паника внутри VM завершает ран с ошибкой, паника внутри тула даёт ошибку вызова; процесс больше не падает;
  - код, который ждёт промис, который никто не разрешит, сразу завершается ошибкой;
  - после остановки VM прерывается повторно, поэтому toJSON с бесконечным циклом больше не держит ран.
- Запись ограничена по размеру:
  - в записи вызова хранится не больше 16 KB аргументов, вывода и ошибки (флаг Truncated), а код получает значения целиком;
  - логи хранят начало и конец, до MaxOutputLength;
  - Value и Error ограничены MaxOutputLength;
  - maxOutputLength у bash не больше 1 MB.
- Отчёты о прогрессе идут не чаще раза в 500 мс, по одному и по порядку. Картинок в них нет: картинки приходят только в итоговом результате.
- Под новую семантику обновлены описание тула, раздел промпта и декларации. В docs/plugins.md добавлено, как плагин-тулы работают в code-режиме.

## Найденные проблемы

### Критично
1. **`edit(p, a, b, {})` роняла весь процесс.** Объект опций без replaceAll давал nil-pointer panic в нативной функции goja. Go-паники goja не перехватывает, поэтому падал процесс раннера; SIGSEGV воспроизведён. **Исправлено.** Для всех входов в VM и для работы вызовов добавлены guard и protect.

### Высокая
2. **Плагин-тулы в code-режиме запускались без окружения раннера.** Окружение состояло только из переменных плагина, без PATH и HOME, хотя docs обещают «besides the runner's environment». **Исправлено.**
3. **Сессия росла квадратично.** Каждый отчёт (два на вызов) нёс полный снимок со всеми выводами: readText до 4 MB, bash без верхней границы. В снимке были и data-URL картинок. Каждое обновление пишется в JSONL. **Исправлено**, см. раздел «Как теперь устроен результат Code».
4. **apply_patch терял правки.** Секции планировались независимо, по содержимому диска. Вторая `Update File` того же файла молча затирала первую. Add и затем Update того же файла падал. **Исправлено:** файлы теперь собираются в памяти. Delete и затем Add тоже работает, а M выводится один раз.
5. **После рестарта Edit и Patch выполнялись повторно.** Правка, где новый текст содержит старый (`foo` → `foo bar`), применялась дважды; патч только из добавлений тоже. **Исправлено:** такие операции завершаются ошибкой и просят перечитать файл. Read, Write и поиск повторяются, потому что они идемпотентны.
6. **Пропущенный аргумент превращался в строку `undefined`.** `write('a.txt')` без содержимого записывал в файл `undefined`. `edit(p, 'x')` заменял на `undefined`. `bash()` запускал команду `undefined`. **Исправлено.**

### Средняя
7. **Раны зависали до RunTimeout (30 мин).** Так было с `await new Promise(() => {})` и с `return` циклического объекта или BigInt: JSON.stringify бросал исключение внутри `.then`. **Исправлено.**
8. **Имена плагин-тулов не совпадали с рантаймом.** Тул `read` объявлялся функцией, но вызывался встроенный read. `delete` и `class` объявлялись функциями, хотя вызвать их так нельзя. `JSON` был объявлен, но не привязан. **Исправлено:** одна проверка `bindable()`, остальные имена объявляются через `tools["name"]`.
9. **Плагин-тул с ненулевым exit считался успешным.** **Изменено:** теперь вызов отклоняется, и в ошибке есть вывод. Аргументы обязаны быть объектом.
10. **Неизвестные опции молча игнорировались** (`{replace_all: true}`), а ошибки ссылались на `old_string` и `replace_all`. **Исправлено.**
11. **console.log показывал Error как `{}`.** Порядок ключей был случайным, потому что json v2 не сортирует map. `throw {…}` давал `[object Object]`. **Исправлено.**
12. **Write, Edit и apply_patch заменяли symlink обычным файлом.** **Исправлено:** запись идёт в цель ссылки.
13. **Гонка данных в `codevm.runCommand`** по полю `timedOut`, найдена через `-race`. **Исправлено.**
14. **Отчёты уходили конкурентно.** Более старый снимок мог прийти последним, и в UI завершённый вызов снова показывался как «running». **Исправлено.**

### Низкая
15. **apply_patch по CRLF-файлам давал смешанные окончания строк.** **Исправлено.**
16. **apply_patch падал на пустых строках.** Пустая строка перед первым `@@` давала «a section adds or removes nothing». Завершающая пустая строка контекста, которой нет в файле, давала «context not found»; codex в таком случае повторяет попытку без неё. **Исправлено.**
17. **Обрезка текста резала UTF-8 посреди руны** в clip, firstLine и сниппетах поиска. **Исправлено.**
18. **TranscriptSearch показывал «record 0»** в заголовках результатов операций и выводил одинаковые сниппеты дважды. **Исправлено.**
19. **`go test ./...` падал на устаревшем тесте раннера.** **Исправлено.**
20. **Мёртвая константа `bash.DefaultTimeout` и неверный комментарий у `RunFile`.** **Исправлено.**

## Не исправлено
- В VM нет setTimeout и setInterval. Ошибка ReferenceError понятная, и есть `sleep()`.
- `bash({timeout: 0})` в коде означает таймаут по умолчанию (600 с), а в Bash-туле `0` означает «без лимита». В коде нет потолка MaxShellTimeout, ограничивает только таймаут рана.
- Плагин-тулы в коде не получают `KOU_CONVEYOR_TOOL_CALL_ID` (это задокументировано).
- TranscriptSearch находит свой же запрос в аргументах текущего вызова. Отменённые операции не ищутся.
- Описание профилей в inspector.js не упоминает TranscriptSearch.
- Пути в codevm не ограничены воркспейсом, как и у Bash; так задумано.
