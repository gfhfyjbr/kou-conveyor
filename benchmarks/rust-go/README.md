# Isolated Rust / Go kernel comparison

This is an experiment, not a replacement engine. It builds three kernels against
current production Go code, ports their selected contracts to Rust, and compares
fresh processes on identical fixtures. No real LLM calls are made.

## Kernels

- **Last external prompt scan**: current `lastPrompt` in
  `cmd/internal/cockpit/sessions.go`, a Go `ReadSlice`/reused-buffer control,
  Rust owned-line and reused-line readers. The logical scan cache is reset;
  this models initial/invalidated reads, not the normal cached fast path.
- **Display snapshot copy**: current `Entry.clone()` from
  `cmd/internal/cockpit/transcript.go`; a Go control with the same types and
  batched backing arrays; Rust owned display DTO and bumpalo request-scoped copies. This covers public JSON fields, not private fold
  state, Rev, Transcript maps or coordinator replay.
- **SSE framing**: port of `harness/primitives/remote_sse.go`, including
  partial frames before errors, CR/LF split boundaries, passthrough offsets
  and frame-size limits. Differential fixtures are generated by the real Go
  implementation, not by a second hand-written reference.

The Rust owned snapshot shares immutable text with `Rc<str>`; mutable arrays,
image metadata and file views are cloned. It is actor-local and is not `Send`;
passing typed snapshots across threads needs Arc or another ownership contract,
which this experiment does not benchmark. The arena variant borrows immutable text and copies mutable
metadata into no-Drop arena values. Its lifetime contract is narrower: consume
it before changing/dropping the source. It is not a drop-in asynchronously
retained snapshot. `arena` reuses/reset a scratch arena; `arena-fresh` recreates
it per request.

## Run from the repository root

Requirements: Go from the root module, stable Rust, Python 3, macOS
`/usr/bin/time -l`. The allocator comparison builds jemalloc from source.

```sh
python3 benchmarks/rust-go/run.py build
python3 benchmarks/rust-go/run.py prepare
python3 benchmarks/rust-go/run.py validate
python3 benchmarks/rust-go/run.py bench --runs 5 --seconds 0.5
python3 benchmarks/rust-go/metadata.py
```

Use the supplied lockfile; normal `build` uses `--locked`.
To skip jemalloc, pass `build --no-jemalloc` and do not leave stale jemalloc
binaries from an earlier build in the output root.

Optional sensitivity controls:

```sh
python3 benchmarks/rust-go/gc_control.py
python3 benchmarks/rust-go/heap_control.py
```

The first uses bounded GC-off loops and GOMAXPROCS=1 in child probes. The second
holds 64 MiB of touched pointer-free live data to test how the GC heap goal
changes the results. Neither changes production. The ballast control is not a
simulation of the real web heap, and its extra RSS must not be charged to Go
in a direct comparison against Rust without the same extra data.

For a real inactive session, append fixtures without changing the source log:

```sh
python3 benchmarks/rust-go/run.py prepare --append \
  --session .harness/sessions/SESSION.session.jsonl
python3 benchmarks/rust-go/run.py validate
python3 benchmarks/rust-go/run.py bench --runs 5 --seconds 0.3
```

The session is copied for log-scan measurements. Its public transcript is
exported by the real Go loader. Size/mtime are checked around copy/export;
choose another session if it changes. Fixture files may contain private user
text, are written mode 0600 to root `rust-go-*.json`, and are ignored by the
repository's existing root JSON rule. Do not commit them.

An optional `bench --only scan`, `--only snapshot`, `--only sse`, or fixture-name
substring selects jobs. It replaces the result files with that subset.

## Outputs

All generated binaries, fixtures, logs and measurements go to the workspace
root, prefixed `rust-go-`. Binaries use the already ignored `.test` extension.
Source remains under this directory; `target/` is ignored.

- `rust-go-validation.json`: equality checks and supported contract.
- `rust-go-results.json`: raw repeated measurements and calibration.
- `rust-go-summary.json`: medians and ranges.
- `rust-go-results.md`: readable table.
- `rust-go-build-*.txt`, `rust-go-go-tests.txt`, `rust-go-rust-tests.txt`: logs.

Go uses overlay-injected test files. No probe is written into a production
package, no app source is patched, and no production process is restarted.

## Interpretation

- Rust timing and RSS use uninstrumented binaries. Separate `count-alloc`
  builds count requested allocation bytes/calls; counter overhead is excluded
  from the timing comparison.
- Go allocation sizes include runtime size-class rounding. Rust requested
  Layout bytes do not include allocator headers/usable-size rounding. Compare
  these as diagnostic allocation measures, not equal definitions of heap RSS.
- RSS and peak footprint are whole-process high-water marks, including startup,
  fixture parsing and warmup. They are not isolated kernel-only peaks.
- Kernel wall time and OS-accounted process CPU time exclude fixture load.
  Go samples getrusage; Rust samples Darwin clock() (user + system CPU across
  threads). Warm filesystem cache is not cleared. Repetitions are interleaved
  in a deterministic shuffled order and run serially.
- Go GOGC=50 matches the web default, with GOGC=100 as a control. The probe
  unsets GOMEMLIMIT; no production GC setting is changed.
- Go runtime GC CPU counters are estimates. They must not be presented as an
  exact percentage of OS-accounted CPU.
- Better results on display DTO copies do not establish parity or the speed/RSS
  of a full Rust runner, web server, GPUI renderer or application.

## Checks

```sh
cargo test --locked --manifest-path benchmarks/rust-go/Cargo.toml
cargo fmt --check --manifest-path benchmarks/rust-go/Cargo.toml
python3 -m py_compile benchmarks/rust-go/run.py
```

The Go differential reuse test and selected production SSE tests also run under
`-race`. On this machine the native test toolchain uses installed macOS 15.2 SDK
with the selected clang; this is a per-command environment setting, not a global
Xcode change.
