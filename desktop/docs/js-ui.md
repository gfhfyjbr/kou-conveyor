# Интерфейс kou desktop на JavaScript

Окно использует существующий QuickJS runtime и GPUI renderer. JavaScript
строит дерево элементов, Rust передаёт данные и выполняет команды. WebView,
Electron, браузер и отдельный Node-процесс для запуска приложения не нужны.

## Где менять внешний вид

| Плагин | Область |
| --- | --- |
| `workspace` | Компоновка окна (`shell`), вкладки, заголовки панелей, переименование вкладки, уведомление, оболочка страниц плагинов (`pluginPage`) |
| `rail` | Проекты, сессии и список агентов слева |
| `screens` | Стартовые экраны, выбор агента, история сессий, оболочка и разделы настроек (`settingsFrame`, `settings`) |
| `appearance` | Пресеты, библиотека тем, редактор 26 цветов, превью, импорт и ссылки (`appearance`) |
| `composer` | Поле сообщения и его кнопки для Cockpit и Studio; очередь и строка состояния Cockpit |
| `studio` | Сообщения, ответы, заголовки вызовов инструментов, рассуждения, план, уведомления, свёрнутая работа, пустое состояние, строка состояния и компоновка поля Studio |
| `chat` | Cockpit, общие меню, модели, карточки инструментов и вложенных агентов |
| `canvas` | Панели управления, меню, инспектор, оформление узлов и связей |
| `usage`, `genui` | Использование аккаунтов и интерактивные поверхности агента |

Исходники находятся в `plugins/<name>/desktop/*.js`. Манифест рядом указывает
точку входа. Новые `appearance` и `studio`, как и остальные плагины,
включаются в бинарник через `crates/kou-desktop/src/plugins.rs::BUILT_IN`.

## Что остаётся в Rust

- Сессии, модели, аккаунты, сохранение, выполнение действий, процессы агентов.
- Проверка документов тем и ссылок, системный обработчик `kou-theme://`.
- IME, выделение, буфер обмена, клавиатурные команды и текстовый редактор.
- PTY/терминал, формирование текста и Markdown, изображения, виртуализация
  транскрипта, анимации и измерение геометрии.
- Перемещение и масштабирование canvas, resize/drag жесты, управление фокусом.

Эти компоненты предоставляются как `ui.slot(name)`. В настройках слоты
`name`, `color`, `link`, `accountName`, `accountProxy` содержат нативный
текстовый контрол; рамки, размеры, фон и окружающая форма задаются в JS.
Обработчики приложения проверяют аргументы команд, даже если пользователь
заменил скрипт интерфейса.

У библиотек `kou-thread-view` и `kou-canvas` сохранён нативный резерв для
использования вне desktop и ошибок расширений. В том числе сложные
редакторы, изображения, разрешения и содержимое инструментов могут занимать
нативные слоты. Перенос не означает удаление всех элементов GPUI из Rust.

## Данные и события

```js
kou.view({
  id: "appearance",
  render(ctx) {
    return ui.col({ gap: 12 }, [
      ui.text(ctx.data.draft ? "Edit theme" : "Choose your theme"),
      ui.button("Create a theme", {
        onClick: (api) => api.act("theme.create"),
      }),
    ]);
  },
});
```

`ctx.theme` содержит общую палитру и метрики. Локальное состояние можно
хранить через `api.setState`; обработчик сбрасывает кеш затронутого chrome
view, поэтому изменение JS-состояния видно и без изменения Rust-данных.

`appearance` получает `presets`, `saved`, `system`, `draft`, `token`,
`editing`, `importing`, `message`, `problem`, `lowContrast`. Цвета документов
передаются как целые RGB; скрипт переводит их в `#rrggbb` для превью.
Действия: `theme.select` (`preset`, `id` или `system: true`), `theme.create`,
`theme.edit` / `theme.delete` (`id`), `theme.share`, `theme.import`,
`theme.preview`, `theme.token` (`token`), `theme.color` (`color`),
`theme.save`, `theme.cancel`, `theme.reset`. Раздел настроек меняется через
`settings.page` (`page`).

`composer` получает `look: "cockpit" | "studio"` и прежние `controls` и
`slots`. `field.send`, `field.force`, `field.stop`, `field.attach`,
`field.model`, `field.effort`, `field.mode` выполняются одним нативным
контроллером в обоих вариантах. Поле не имеет рамки при idle, работе агента
или фокусе. Forced-сообщения используют обычный фон сообщения.

## Ссылки в сообщениях

Markdown-ссылки на абсолютные файлы, относительные пути и локальные `file://`
открываются системным приложением. Относительный путь считается от каталога
проекта конкретного чата. Пробелы и URL-кодирование поддерживаются; `:42`,
`:42:7` и фрагменты `#L42` не становятся частью имени файла. Системное
открытие пока не позиционирует редактор на указанной строке.

Ссылка `kou-theme://` открывает предпросмотр темы в настройках. Отсутствующий
файл вызывает уведомление. Обычные веб-ссылки открываются в браузере;
произвольные протоколы не передаются системе. Маршрутизация общая для Cockpit,
Studio и Markdown в результатах инструментов.

## Перезагрузка и восстановление

Приоритет источников: встроенные скрипты → checkout → пользовательские
`plugins/` в каталоге приложения. Изменения подхватываются существующим
watcher без пересборки Rust. Ошибка загрузки новой версии сохраняет последнюю
загруженную версию.

Обязательные представления окна и настроек используют `core_chrome`.
Если live-плагин отсутствует, не содержит нужного view или падает во время
render, запускается встроенная JS-версия в отдельном interpreter. Её клики
отправляются именно в этот interpreter; они не попадут в обработчики
сломанного override. Дублирующая Rust-разметка настроек удалена.
Остальные расширяемые части сохраняют существующий нативный резерв.

## Проверка

Интеграционные тесты проверяют создание темы кликами и вводом, сохранение и
импорт; переключение настроек, даже когда override падает; Studio-копирование
сообщения, выбор режима, очередь и остановку агента. Существующие проверки
покрывают hot reload, canvas, чат, меню, фокус и геометрию.

Для проверки кадров есть сцены `shell-settings-charcoal`,
`shell-settings-white`, `shell-settings-editor`, `shell-settings-account-form`,
`shell-chat-studio`, `shell-chat-working`, `shell-chat-force`:

```sh
kou-desktop --scene shell-chat-studio --capture /tmp/studio.png
kou-desktop --scene shell-settings-charcoal --width 760 --capture /tmp/settings.png
```
